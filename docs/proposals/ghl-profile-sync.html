GoHighLevel Profile Sync

Keep member profiles in the app and contacts in GoHighLevel in step, in both directions, and add the details Curated Introductions needs. This comes before Curated Introductions is built.

Draft for review · 24 Nov 2026 Not built yet

Where things stand

The app already copies contact details from GoHighLevel into member profiles: on every sign-in, whenever a contact changes in GoHighLevel, every night at 06:00 UTC, and when an admin presses Sync from GHL. Nothing flows back. A member who changes their title in the app leaves GoHighLevel out of date.

This proposal makes the sync two-way, adds four details, and limits it to the members it should cover.

Who is covered

  • Members tagged member-active-SD, the San Diego community. Tags are matched regardless of capitals.
  • A new community gets its own tag, such as member-active-OC for Orange County, added to the app's tag list when it launches.
  • Sign-in and access for other contacts (guests, hosts, referral partners) stay as they are.

How the two-way sync works

  1. The latest change wins, wherever it was made. An admin's correction in GoHighLevel reaches the app, and a member's edit in the app reaches GoHighLevel.
  2. A member's edit is saved to GoHighLevel first, then to the app. If GoHighLevel can't be reached, the member is told to try again and nothing is saved. Otherwise the nightly sync would put GoHighLevel's old value back over the member's change.
  3. A blank in GoHighLevel never wipes a value in the app. GoHighLevel sends an empty field and a missing field the same way, so a blank can't be read as "delete this". This is how it works today.
  4. No loops. When the app writes to GoHighLevel, GoHighLevel tells the app the contact changed, and the app finds nothing new to copy.
  5. Gender tags are one at a time. If a contact has more than one in GoHighLevel, the app treats gender as unanswered until an admin fixes it, and tells the admin.
  6. Gender tags stay private in the app. The app keeps a copy of each member's tags, and today other members' devices can receive that copy along with a profile. Gender tags are therefore taken out of that copy and stored only in the private Curated Introductions record, which only admins and the matching can read.
Found while checking this: the endpoint that loads another member's profile returns their whole member record, including email, phone and tags, even though the profile page shows only some of it. It should return only what the page shows. This is worth fixing with the sync, whatever happens with gender.

Setup in GoHighLevel

  1. Create the tags gender-male, gender-female and gender-pns.
  2. Before deleting the Community and Gender fields, check that no workflow, smart list, form or template uses them. The app doesn't read either field.
  3. Keep using the standard Date of Birth field.

To confirm

  1. How should an email change work?Suggested: the member enters the new address, receives a confirmation link there, and the change reaches GoHighLevel and sign-in only after they click it. Without that, one typo locks a member out.
  2. Should the app say "Organization" instead of "Business name"?Suggested: yes. It covers non-profits, government, religious organizations and the self-employed. GoHighLevel keeps its own label.
  3. If a member already has a gender answer in the app, should it be added to GoHighLevel as a tag?Suggested: yes, once, so GoHighLevel starts complete.
  4. Should pictures go to the GoHighLevel media library?Suggested: later, as a small separate task, since it isn't essential.

Then

Once this is in place, the Curated Introductions work can rely on every San Diego member's profile having the details it needs, or on prompting them for what's missing.
